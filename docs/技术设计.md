## 2. 算法

### 2.1 固定回看窗口评分

```
e_H(t) = || p(t) - [p(t-H) + v(t-H) * H] ||     # 本车固定 H 秒回看窗口内的运动变化
B(t)   = 1 if a_long(t) <= -a_brake else 0      # 急刹标记
S(t)   = clip(e_H(t) / E_scale, 0, 1)           # 归一化评分
```

- `p`、`v`、`a_long` 只取本车自身历史；`e_H` 与发包时刻无关，发包不清空历史。
- 采样点不恰好落在 `t-H` 时，所有策略使用同一插值规则；历史不足 `H` 时令 `S=0`，急刹检测与基础反馈照常工作。
- 直路场景可用纵向位置与速度计算。

### 2.2 四组策略（只切换最终倍率 W）

| 策略 | W | 说明 |
| --- | --- | --- |
| G0 | `1` | 公共 CBR 反馈基线 |
| G1 | `clip(v / v_ref, 1, 1+beta)`，`v_ref = 33 km/h` | 速度权重基线；不引入密度控制 |
| G2 | `1 + beta * B` | 只保护达到门槛的急刹 |
| G3 | `1 + beta * max(B, S)` | 急刹 + 固定窗口运动变化 |

同一次运行内各组共用消息、CBR 估计、发送定时器与日志框架，只替换 `W`。

### 2.3 公共 CBR 反馈环

```
Cbar_k = 0.8 * Cbar_(k-1) + 0.2 * C_k
error_k = C_target - Cbar_k
b_(k+1) = b_k                           若 |error_k| <= h
b_(k+1) = clip(b_k + eta * error_k, b_min, b_max)   否则
r = clip(b_(k+1) * W, r_min, r_max)
```

首个完整窗口初始化 `Cbar`；每个 tick 先更新 `Cbar` 与 `b`，再按本组 `W` 计算 `r`。各车 `b` 独立反馈，共用控制**不保证**实测 CBR 相同。`r` 是目标生成率，不是成功接收率。

### 2.4 发送定时器（必须与控制事件分离）

- 到期点 = 上一次实际下交 MAC 的时刻 + 当前目标间隔；每个间隔的抖动只抽一次。
- 调率后若到期点已过，只安排一次满足最短间隔的最近可行发送，**不追赶积压包**；任何时刻只保留一个待发送事件。
- 第一次发送使用固定种子的独立初始相位。
- 消息在发送时才装载最新状态并记录 `genTime`，紧接下交时记录 `submitTime`。
- `B=1` 且 `b` 相同时，G2 与 G3 目标率相同，不能假设 G3 的第一包一定更快。

## 3. 接收判定与指标

| 指标 | 定义 |
| --- | --- |
| `D_update` | 首个 `genTime >= t0` 且通过普通有效性检查的状态包接收时刻 − t0 |
| `D_info` | 首个**有效制动信息**接收时刻 − t0（含检测、等待发送、网络接入） |
| `D_action` | 实际反应制动时刻 − t0；仅闭环驾驶时有定义，主实验标为不适用 |
| `Age(t)` | `t − 最后有效状态 genTime` |
| `E(t)` | `|p_true(t) − p_hat(t)|`，`p_hat = p_last + v_last*(t − genTime_last)`，仅离线评价 |

事件结果计数规则：

- 期限内收到有效信息：记实际 `D_info`，不计超时。
- 期限后但观测窗内收到：记 `D_info`，并计超时。
- 观测窗结束仍未收到：`D_info` 留空，同时计超时与未收到/右删失（两类不互斥）。
- 真实急刹已发生但未检测：保留事件，无有效信息按未收到处理，单列检测失败原因。
- S0 无新急刹：事件延迟与超时记为 `N/A`（不填 0），单独统计估计与开销。

`t0` 前生成、`t0` 后到达的旧包不能算新状态更新。超时比例的分母是全部有效的预定事件车对；未实际生成的事件必须标为运行异常并留记录。

## 4. 统计单位

- 每个配置先做 5 个独立种子，四组**按相同种子配对**。
- 先在单次运行内汇总，再比较种子级差异；包、车对、同次运行内的事件都**不**当作独立重复。
- 成功事件的 p50/p95 须附成功数与总数；数量不足时保留原始散点并说明限制。
- 5 个种子下无显著差异，不构成等价性证明。

## 5. 日志公共契约

- 所有 CSV 至少含 `run_id`；由同目录 manifest 映射策略、场景、负载、种子与版本。
- 跨运行的相同 `seq` 不是同一个包。
- 字段落地后固定 `schema_version`。
- 分别记录：实际下交数、实际接收数、原始 CBR、平滑 CBR、背景车辆 Age 及缺失比例；目标率 `r`、生成次数、空口成功发送数、接收数不得互相替代。

## 6. 实验阶段与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 环境与基线 | G0–G3 seed 0 基线、空目录恢复 | 基线与恢复回归通过 |
| P1 正式运行框架 | 任务生成、幂等、断线接续、续跑 | 测试通过；100 个唯一任务、25 个配对块预生成 |
| P2 场景与测量 | S0/S1/S2 场景、物理轨迹、漏收与日志裁剪等价性、资源短测 | 等价性验收；16–960 辆资源数据 |
| P3 校准与放行 | 背景负载两档（低/高）标定 + E1 验收 + 冻结 | 两档各自两个种子全部窗口合格；否则网格耗尽 |
| P4 正式矩阵 | 100 次有效运行、25 个完整配对块（S1 40、S0 40、S2 20） | 每完成一块即持久归档并核验，失败暂停下一块 |
| P5 主线分析 | 逐运行指标与配对差 CSV、F1–F6 六图、报告与最终归档 | 干净英文路径复跑一个配对块核对，再由原始日志重建六图 |

高档负载的判定是双门槛：每个目标车每个窗口 CBR 在 50%–65%，且 90 s 长窗内至少 25% 的时间控制目标发送率落在 (1+1e-6, 9.5] Hz。

## 7. 当前状态（截至 2026-11-23）

- E0：6 个可测密度 × 2 种子 = 12 次有效运行，判定 `grid_exhausted`；低档选定 5 辆/km/车道（单车窗口 CBR 8.13%–8.58%），高档最高 40.80%，差 9.2 个百分点。
- 几何条件排除了密度 1、2（同车道找不到 10 对符合距离要求的背景车）。
- 正式矩阵未执行（部署模型的设计限制见报告第 6 节）；补充实验（16 + 4 + 20 次）单独归档，不改变正式计数。
- 已排除漏插、观察者附近车流消失、道路边缘均值稀释等解释；结论只覆盖已测设置。
