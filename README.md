# EIE575-Project

**TABR** — Transient-Aware Beacon Rate Control for Sudden Braking under Highway Channel Congestion
高速信道拥塞下，针对突发制动的瞬态感知信标速率控制。

EIE575 课程项目（Group 3）。平台为 OMNeT++ 5.6.2 + Veins 5.0 + SUMO 1.6.0、V2V 单跳 IEEE 802.11p，比较四种广播速率分配策略在急刹场景下的信息及时性、跟踪误差与资源代价。

**现状一句话**：工具链、场景、校准与主实验已完成，报告与 deck 已交付；100 次正式矩阵未执行，原因是部署模型的设计限制（见报告第 6 节）。详见 [进度说明.md](进度说明.md) 与 [REPORT_20261124.md](TABR_project/docs/REPORT_20261124.md)。

## 研究问题

拥塞控制会让刚产生的制动信息排队等待，即使两车已经在通信范围内。项目要回答三个命题：

| 命题 | 内容 |
| --- | --- |
| H1 | 在部分拥塞的突发制动条件下，急刹权重 G2 是否比 G0/G1 改善延迟或超时？若收益靠显著增加发报量换来，须一并报告资源代价 |
| H2 | 加入固定回看窗口运动变化的 G3，是否比 G2 还有额外收益？若两者相近而 G3 开销更大，就保留更简单的 G2 |
| H3 | 已经知道且保持静止的队尾是否需要频繁更新（S0 对照）；多车同时急刹是否会加剧拥塞（S2 压力测试） |

## 四种策略

所有策略共用消息格式、MAC 优先级、CBR 反馈环与发送定时器，**只切换最终速率倍率 W**：

| 策略 | 最终倍率 W | 作用 |
| --- | --- | --- |
| G0 | `W = 1` | 只有公共 CBR 反馈，拥塞控制基线 |
| G1 | `W = clip(v / 33 km/h, 1, 1+beta)` | 论文启发的速度权重基线（不是论文复现） |
| G2 | `W = 1 + beta * B` | 只保护达到门槛的急刹（B 为急刹标记） |
| G3 | `W = 1 + beta * max(B, S)` | 急刹 + 固定窗口运动变化 S |

其中 `B(t)=1` 当实际纵向加速度 ≤ −a_brake；`S(t)=clip(e_H/E_scale, 0, 1)`，`e_H(t)=‖p(t)−[p(t−H)+v(t−H)·H]‖` 只用车自身历史计算，回看窗口固定、发包不清空历史。

## 三个场景

| 场景 | 内容 | 主要评价 |
| --- | --- | --- |
| S1 | 正常行驶与通信 20 s 后前车急刹（80 km/h、6 m/s²、净距 25 m、总长 120 s） | 首次收到有效制动信息的时延 D_info、超时率、跟踪误差 |
| S0 | 四组在相同时刻获得完全相同的静止队尾先验，队尾保持静止 | 估计误差、广播开销、对其他车辆的更新代价 |
| S2 | 多车同步制动的压力测试 | CBR 峰值、超阈时长、恢复时间、事件送达 |

背景无线负载由 E0 校准后冻结，低、高两档；事件前速度与背景密度分别变化，避免把低速、排队和信道拥塞混成一个因素。

## 边界

- 研究目标是识别收益、代价与适用边界，**不声称降低了真实事故概率**。
- G1 借鉴 Speed-Aware V2X Congestion Control 的按状态分配思路，建立同平台速度基线，不把 Veins 数值称为该论文的复现。
- 所有结论限定在已测的消息、控制器、PHY/MAC、速度与四车道设置内，不外推到其他无线参数。
