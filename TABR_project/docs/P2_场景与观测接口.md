# P2 真实引擎与验收

采用原 Veins/OMNeT++/SUMO，保留两车 smoke。正式模式用 run 级流和预登记文件，测量模式仅改变记录范围。CSV 的公共字段由 tools/formal_analyze.py::HEADERS 定义。t=0 是 SUMO 初始位置，Veins 默认首轮运动回调在 0.1 s。首次真实在场时间必须取自实际回调。

## 交通与登记

用户于 2026-11-22 确认所有正式密度保持均匀排布。8 km 四背景车道的 1、2 辆/km/车道候选若无法登记十对距离 20–250 m 的车辆，标明几何不合格和实际候选数。5、15、30 先做资源和场景检查。16/64 辆的工程资源短测使用目标附近均匀预填的有限路段，报告实际车数、间距、测试时长，这两种配置仅验证资源。真实长测与全部低高档保留全长空间设定。

输入为 events.csv、pairs.csv、prior.csv、vehicles.csv、phases.csv 和独立生成的有效 net/route/sumocfg/launch/ini/radio。仿真不依赖接收结果控制车辆。统一纵向坐标、测试零速先验和车头间距，独立真值数据按原计划覆盖目标和十对背景车辆。S2 四个 sender 的同名本地事件可分别对应不同物理事件。

## 测量与验证

run 级 CSV 每类一个流。登记目标与背景对保留完整状态和发送包关联证据，所有节点记录控制窗、资源计数及生命周期；固定审核车辆记录 MAC 忙时边沿。对照 full 和 registered_pairs 使用相同种子、轨迹、消息和随机调用，分别测试相同计数、真值和研究指标。独立初相位和随机抖动按每车种子重放。进程级峰值句柄、内存、输出字节均实测。

SUMO-only 先检查插入时间、目标真实减速度、停车、碰撞/瞬移与目标和背景车对在场。真实联合重复同一诊断，并从 logs 中校对 TX、RX、防重、先验、窗口、应用集合、控制器与独立真值。短资源走查不产生有限期通信指标；正式场景工程走查走完整分析出口。有效漏收/超期也要能完整生成结果。
