# TABR 核心仿真实施手册

研究规则以 EIE575_Simulation_Execution_Plan.md 正文为准。在 P0 固定包之后实现正式模式。已有 C++ 控制器、SUMO/Veins、MAC、MCP 客户端和历史 smoke 继续提供对照。新代码解决旧入口只能接纳两车、已送达且按时的单事件场景这一限制。

## P1 正式入口与离线验收

- 使用已装 Python 3.13/标准库编写机器配置、批次和离线分析。项目的 run.ps1 保持 smoke 的原行为。experiment.ps1 负责正式入口，Python 可直接调用。配置的完整预注册规则进入每次结果快照。
- 每个 attempt 含 config_snapshot.json、run_manifest.json、inputs/（events.csv、pairs.csv、prior.csv 和有效场景文件）、logs/（单表 control_log.csv、tx_log.csv、rx_log.csv、detection_log.csv、scenario_truth.csv、state_log.csv、busy_audit.csv、event_log.csv、lifecycle.csv）和 metrics.json。尽可能复用原列名，研究时间列保留准确 SimTime。汇总前验证文件、键、覆盖与来源。
- 先 validate 和 plan，锁定 25 个配对块和 100 个唯一 job，再由候选/冻结状态限制真实启动。S1、S0、S2 按此顺序；恢复时检查版本与全部哈希，保留独立 attempt。0=有效、2=配置、10=环境、20=引擎、30=数据、40=未完成。
- 每个登记物理事件先按 sender 关联检测，再投影到登记 pair。实际未检、未收和超期保留分母。S0 的先验和真实接收分开。时刻端点、独立真值、占用率总体和 S2 恢复规则遵照计划第 8 节。
- 合成用例写到临时目录，包含无事件/无包、时刻边界、同 ID 多 sender、损坏文件、已完成文件被破坏及改版重试。历史 G3 seed0 对照用于核对掩码。通过命令应输出逐项结果。真实接入和校准分别在 P2 与 P3 取得证据。

## E0 负载判定与空间统计

`python -B tools/calibrate.py measure <attempt>` 读取每次校准的配置、车对、控制窗、独立 MAC 忙闲转换、车辆生命周期、SUMO 诊断和局部背景车数。`python -B tools/calibrate.py decide --config configs/core.json [attempt ...]` 重新核验原始证据，返回下一组密度、预热和种子。候选未齐退出 40，数据无效退出 30，选档完成退出 0。合成数据必须标记为 synthetic，decide 加 --synthetic，结果只用于测试。

每个校准窗对目标双车、登记背景接收车、两端边缘背景、全车分别输出车辆数、有效车辆秒数、先按每车暴露时长取平均后车辆等权的原始 CBR，以及全体车辆秒加权 CBR。边缘样本取控制窗终点时距离任一端点不超过 1000 m 的背景车，用 SUMO 道路自身纵向 `lane_position_m`（前保险杠）判定。跨统计边界的控制窗按时间重叠拆分。无有效观测时均值为 null。选档只使用固定目标双车的两种子逐窗判据。

资格表依第 11 节先收齐三档六次，必要时按 20→40→60 秒复核稳定性，再按登记的额外候选继续。共同预热不一致时逐一核验两档两种子，复用同配置已完成证据并补跑缺项。种子结果分歧不取平均，工程无效的数据修复后重试。`python -B -m unittest discover -s tests -p test_calibrate.py -v` 检查上述规则和空间权重手算样例。

E0 正式均匀预填的稀疏档可在登记阶段排除。`calibrate.py decide --config configs/core.json --geometry-exclusions <seed100的scenario.json> <seed101的scenario.json> -- <已执行的attempt目录>` 接受原始登记结果。每档两种子都要重放当前生成器，核对 8 km 道路、车道数、预填辆数、邻车间距、10 对与 20–250 m 规则、完整筛选计数。只有均匀间距超出上限且候选对确为零，才记录排除并继续下个候选。缺一个种子时返回 geometry_evidence_required；无证据仍按原流程走查。geometry_exclusions 列表保留原报告路径和哈希，measured_cbr 为 null，wireless_runs 为 0，不计入 completed_unique_runs，也不对排除档延长预热。

## P3 E0 真实运行

`./experiment.ps1 -Action calibrate -Config configs/core.json -Status` 查询当前校准状态。去掉 `-Status` 后，驱动核对 P2 验收和当前可执行文件哈希，通过正式 MCP 逐次提交、监控，并从实际 attempt 原始日志复算。加 `-Once` 只向前推进一步。每档称为 candidate，只有两个种子的测量与统一预热复核通过后才写入低/高档选择。`results/calibration/<版本>/index.json` 保留每次请求、失败尝试和原始证据入口，`measurements` 存逐车测量及拒选理由，`decision.json` 给出当前决策。中断后复用原请求编号，工程失败保留后可用 `-RetryFailed` 补新尝试。完成 E0 只放行 E1 工程验收。
